# Version / Sound プルダウン外観統一 — 設計仕様

- 作成日: 2026-07-20
- ステータス: Design（承認済み）
- 対象: Main `VersionSelector` / Sub `AudioSelectDropdown`

## 背景

Main ウインドウの Version 選択と Sub ウインドウの Sound 選択は、大量の候補を扱うため独自の仮想スクロール式プルダウンを使用している。一方、閉じた状態の入力、メニュー面、選択・hover 色がそれぞれ独自実装であり、同じ画面で使われる Yamada UI の標準 `Select`（Sub の Variant など）と外観が揃っていない。

Version はダウンロード状態表示と分類見出し、Sound は検索入力を必要とするため、標準 `Select` への置換は行わない。既存機能を維持しながら、共通のスタイル定義を両コンポーネントへ適用する。

## 目標

- Version と Sound の閉じた状態を、既存の標準 `Select` と同じ視覚言語に揃える。
- メニューの背景、境界線、角丸、影、hover、選択状態を統一する。
- ライト／ダークテーマの双方で自然に表示する。
- 検索、仮想スクロール、キーボード操作、状態アイコンなど、現在の機能と操作性を維持する。
- 共通スタイルを一箇所に置き、今後の見た目のずれを防ぐ。

## 非目標

- Yamada UI の標準 `Select` への置換。
- Version / Sound の候補取得や選択ロジックの変更。
- リストの並び順、分類、表示件数、ダウンロード処理の変更。
- Sub の Variant、Pitch など、すでに標準 `Select` を使う入力の変更。
- アプリ全体の配色、タイポグラフィ、レイアウトの再設計。

## 採用アプローチ

共通の「仮想 Select」用スタイル定義を追加し、`VersionSelector` と `AudioSelectDropdown` が同じ意味のスタイル値を参照する。

共通化の対象は視覚表現に限定する。Version はボタン型トリガー、Sound は検索可能な入力型トリガーという役割の違いがあるため、状態管理や JSX 全体を一つの汎用コンポーネントへ統合しない。これにより変更範囲を抑えながら、外観の再分岐を防ぐ。

想定する共通化単位:

- トリガーの高さ、背景、境界線、角丸、hover、focus-visible、disabled
- メニューの背景、境界線、角丸、影、トリガーとの間隔
- 行の通常、hover / active、selected 表示
- 補助文字色

## ビジュアル設計

新しいブランド表現は追加せず、アプリ既存の Yamada UI テーマをデザインシステムとして使用する。固定 HEX 色は導入せず、ライト／ダークへ追従するセマンティックトークンを用いる。

### トリガー

- 標準 `Select` と同等の高さ、角丸、1px 境界線、水平パディングにする。
- 通常時は標準入力と同じ背景・文字色を使う。
- hover 時は標準入力に準じた境界線変化を使う。
- `:focus-visible` は標準 `Select` と同等の明確なフォーカスリングを表示する。
- disabled 時はテーマ標準の無効状態（不透明度とカーソル）へ揃える。
- 右端に下向きシェブロンを置き、開いている間だけ 180 度回転させる。
- Version の左端にあるダウンロード済み／未ダウンロードアイコンは維持する。
- Sound は閉じている間は選択値を表示し、開くと同じ領域が検索入力として機能する。

### メニュー

- トリガー下に 4px の間隔で表示する。
- 背景、1px 境界線、角丸、影を標準 `Select` のリストに合わせる。
- 幅はトリガー幅と一致させ、現在の z-index と仮想リストの最大高さを維持する。
- Sound にある `gray.800` / `gray.600` の固定色は廃止し、ライト／ダークテーマへ追従させる。

### 候補行

- 通常行はメニューの文字色と透明背景を使う。
- hover とキーボード active は同じ背景色にする。
- selected は accent の淡い背景と通常の可読な文字色で示す。現在の Sound の全面ブルー＋白文字は使わない。
- 行高と左右余白は両方で統一する。ただし Version の分類見出しも同じ固定行高に収め、仮想スクロールの計算を維持する。
- 長い値は一行省略表示し、既存の `title` による全文確認を残す。

### タイポグラフィと動き

- フォントはアプリ既存の UI フォントを継承し、新しい書体やサイズ体系は追加しない。
- シェブロンの回転のみ短いトランジションを残す。
- 新規の装飾アニメーションは追加しない。

## 挙動の維持

### Version

- Release / Snapshot / Pre-release / Release candidate の分類見出し。
- ダウンロード済み／未ダウンロードのアイコン。
- ArrowUp / ArrowDown、Enter、Escape の操作。
- 選択位置へのスクロールと `react-window` による仮想化。
- 外側クリックで閉じる動作。

### Sound

- 空白区切り AND 検索。
- フォーカス要求時の自動オープン、全選択。
- ArrowUp / ArrowDown、Enter、Escape の操作。
- `react-window` による仮想化。
- 外側クリックで閉じる動作。

Sound の外側クリック判定は現在メニュー要素だけに ref が付いている。外観変更に合わせ、トリガーを含むルート全体を判定対象に統一し、トリガー操作と外側クリックが競合しない構造にする。ただしユーザーから見た開閉仕様は変えない。

## アクセシビリティ

- Version で既に使用している `aria-haspopup="listbox"` / `aria-expanded` / `role="listbox"` / `role="option"` を維持する。
- Sound にも同等の combobox / listbox 関係と選択状態を付与する。
- キーボードフォーカスを色だけでなくフォーカスリングで示す。
- アイコンは装飾扱いとし、選択値の読み上げを妨げない。
- 入力・候補の既存キーボード操作を回帰テストする。

## エラー・空状態

- 候補が空の場合、空の仮想リストを描画しない。
- Sound の検索結果が 0 件の場合も、高さ 0 のリスト面を表示しないか、既存 UI の文体に沿った短い空表示を使用する。実装時には不要な新規文言を避け、視覚的に空のポップアップが残らないことを優先する。
- 候補取得や選択時のエラー処理は本変更の対象外とする。

## テスト方針

この変更では、共通スタイル定義の適用とアクセシビリティ属性を静的・コンポーネント単位で検証できるテストを先に追加する。既存のテスト基盤で DOM レンダリングが難しい場合は、共有スタイルの純粋な定義を検査する self-check を追加し、TypeScript / ESLint / build と手動確認を組み合わせる。

手動確認項目:

1. Main の Version と Sub の Sound / Variant が、閉じた状態で同じ高さ・角丸・境界線・背景に見える。
2. ライト／ダークの双方でメニュー面と文字のコントラストが保たれる。
3. hover、selected、focus-visible が両プルダウンで同じ規則に見える。
4. Version の分類、状態アイコン、選択、キーボード移動が従来通り動く。
5. Sound の検索、フォーカス要求、選択、キーボード移動が従来通り動く。
6. 長い Version / Sound 名が省略表示され、ツールチップ相当の `title` で全文を確認できる。
7. disabled 状態が標準 `Select` と同じ見た目になり、操作できない。
8. 候補または検索結果が空でも、不自然な高さ 0 のメニュー枠が残らない。
